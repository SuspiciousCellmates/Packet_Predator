# Architecture audit — 2026-07-20

## Executive finding

The prototype demonstrates packet construction, decoding, radio access, a web interface, and an in-process simulation, but it combines at least four products: packet workbench, Game Controller, God Tool-like controls, and scenario simulator. Shared protocol definitions have also diverged between Python and STM32. The foundation checkpoint therefore freezes behavior and establishes ownership before refactoring.

## Findings

### Protocol authority is duplicated and conflicting

`packet/packet.py`, `packet/payload_values.py`, `nodes/node.py`, and `web_app.py` define Python message, event, node, and setting values. `GameControllerBasic/Core/Inc/radio.h` independently defines an STM32 variant. Type 5, CONFIG layout, ACK/NACK behavior, radio band/channel, and CRC defaults conflict. Python setting indexes 1–3 are reused with contextual meanings and the current reverse-map silently selects the last inserted name.

Disposition: characterize both v0 variants in `../Protocol_Contract`; do not repair or endorse either during foundation.

### The web process owns incompatible responsibilities

`web_app.py` combines FastAPI endpoints, static serving, radio lifecycle, SPI locking, packet history, SSE fan-out, protocol construction, simulation startup, a polling coordinator, and game rules. A task failure can calculate a difficulty-dependent penalty, and sabotage traffic can be relayed automatically.

Disposition: keep capture/manual workbench intent; quarantine coordination and decisions. A later milestone will separate protocol, transport, service, and thin web layers.

### Simulation is autonomous and nondeterministic

`simulator.py` creates threaded virtual actors that choose random tasks, move on a map, complete/fail puzzles, sabotage, and change game state. `driver/virtual_airwaves.py` is an in-process routing mechanism rather than a deterministic replay contract.

Disposition: quarantine autonomous behavior. Later replace it with deterministic replay/fake transport and explicit scenario tooling outside the workbench runtime.

### God Tool-like actions are embedded in the workbench

The API and frontend expose game start/stop, force meeting, force sabotage, kill, reset, map, and difficulty operations. These are game orchestration or privileged operator workflows, not packet-workbench features.

Disposition: preserve only in the archival prototype. Design Game Controller and God Tool separately after the shared protocol and workbench boundaries stabilize.

### Transport and protocol concerns are coupled

The nRF905 driver contains hardware import fallback, register defaults, physical addressing, virtual-airwave routing, and payload transmission assumptions. The process constructs `0xDEADBEEF` repeatedly. Current Python and STM32 radio defaults would not interoperate over air.

Disposition: nRF905 remains experimental. Treat radio configuration as an adapter/deployment concern and validate one physical adapter only after deterministic replay and layering work.

### Global state and concurrency increase diagnostic risk

The process uses global managers, background threads, a main event loop reference, shared queues, and mutable `app.state`. Packet history and simulated state can be mutated across paths, making reproduction and lifecycle failures difficult to isolate.

Disposition: do not change foundation runtime. Target explicit services and deterministic lifecycle boundaries in the later refactor.

### Tests characterize only part of the behavior

The existing ten tests cover selected packet, virtual routing, and simulated-node behavior. They do not establish cross-language conformance, physical transport behavior, API boundaries, authorization, error semantics, or deterministic scenarios.

Disposition: retain v0 characterization tests, add frozen-runtime and scope guard tests now, and defer reference codec/cross-language conformance until after v1 design.

## Foundation conclusion

No runtime fix is safe before ownership and message inventory review. The archived tag preserves the prototype, the sibling contract captures evidence, and the active foundation harness prevents accidental drift while the next decisions are reviewed.
